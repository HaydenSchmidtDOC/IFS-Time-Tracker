New in v0.4.0

A guided first-run tour, plus a smarter, safer Calendar

The headline this round is a short click-through tour for new installs — but there's also a full pass of Calendar-view polish and safety fixes worth knowing about.

  • Guided first-run tour. A fresh install now offers a short walkthrough — adding a project, tracking time, the quick switcher, and a full tour of the Timesheets window (both views, merge, and drag-to-add/edit/resize/delete in Calendar view, mimed on an overlay rather than touching your real data). Skipped it, or want to see it again? Replay it any time from Settings → Start tutorial.
  • Drag to add time in Calendar view. Click-drag empty grid space to highlight a span — showing the snapped time range and, once tall enough, the duration — and release to open the Add dialog pre-filled to it.
  • A note prompt when a live session auto-stops on collision, instead of silently banking an empty note — same as a normal Stop.
  • Smarter manual add times. A fresh entry now defaults to a sensible 1-hour span (or snaps sooner against whatever's next) instead of a fixed length, and an entry that spans one or more existing blocks now splits around them instead of being rejected.
  • Editing a block now shows (and lets you change) its note.
  • Merge sessions is now a one-click toggle pinned to the chart's corner instead of buried in a settings popover, and the Timesheets window remembers whichever view (Totals/Calendar) you last used instead of a fixed default.

Also fixed: a Calendar block no longer visibly jumps/snaps right before its edit dialog opens when you click it; the currently-recording block always shows its title now, even if it started too small to fit one at first; double-click/Enter on the project you're already tracking now stops it, matching the button; the floating pill no longer shows up in Alt-Tab; and an idle discard's note now backfills onto every earlier split of that session, not just the last one.

Known limitations

No undo yet. Deleting or dragging a block applies immediately — a bad drop or misclick means fixing it by hand. Your data folder's OneDrive file history is a partial safety net in the meantime, but it's worth being a little careful.

A block can't be dragged across a month boundary (e.g. the last day of one month onto the 1st of the next) — that specific move is quietly rejected rather than applied.

01

Getting started

  1. Nothing to install. The app is one .exe — copy it wherever you like and double-click it. Windows may show a SmartScreen prompt the first time; that's expected for a new internal tool.
  2. It creates its own data folder next to the exe the first time it runs — your projects, settings, and monthly CSV logs all live there. Nothing is written anywhere else on the machine.
  3. Add your first project with the ＋ Add project button — give it the IFS project code, ASN number, and a name. A colour is picked for you automatically (each new project gets a colour as visually distinct from your existing ones as possible).

Already running an earlier beta build?

Your projects and tracked hours live in a data folder next to the old exe — a new exe on its own doesn't touch it.

Easiest: extract this new version into the same folder as your old install, letting it overwrite the old exe. The data folder next to it is untouched, so everything carries over automatically.

If you extracted it somewhere new instead: copy the whole data folder from your old install into the new one, next to the new exe.

Not sure where your old one is? The old version's Settings → Data location shows the exact path, with an "Open data folder" button.

02

The basics

One button does the work, and it changes meaning based on what's selected:

  • ▶ Start — shown when nothing's running, or the selected project isn't the live one. Or just double-click a project to start it immediately.
  • ■ Stop — shown when the project you have selected is the one currently tracking.
  • ⇆ Switch — shown when a different project is selected while one is already running. It banks the current block first, then starts the new one — no time is lost in between.

Selecting a project in the list never starts it by itself — you always have to confirm with the button, Enter, or a double-click. Enter or a double-click on the project that's already running stops it, same as pressing the button.

06

Notes & away time

  • Optional notes — if enabled in Settings, you'll be asked for a short note whenever you stop or switch away from a project. It's skippable; press Enter to leave it blank.
  • Away-time prompt — if your PC locks or sits idle past the configured threshold while a project is running, you'll be asked "Away for N min while tracking X. Keep that time on the timesheet?" on your return, with Keep or Discard.

08

Settings

Opened with the ⚙ Settings button on the main window. Closing it with unsaved changes will ask whether to save, discard, or go back.

Tracking

Note prompt, pill/tray visibility, start minimised, start with Windows, and the idle threshold (minutes).

Projects

Add, edit, or remove projects — code, ASN, name, and colour.

Data location

Shows where your data lives (this OneDrive folder, by default — that's what makes it sync) and lets you point it elsewhere if needed.

Timesheet-view settings — the calendar drag-snap granularity, minimum split-block size, and how aggressively small segments fold together in Totals view — live in their own popover instead: the ⚙ in the bottom-right corner of the Timesheets chart. They apply immediately as you change them, no Save button. Merging sessions is a separate one-click toggle right next to it, and the window itself remembers whichever view you last had open.

09

Exporting to IFS

Settings → IFS export mapping lets you define exactly which columns come out, and in what order — each row is "this IFS column ← this piece of data." Pick a month with the arrows and press ⇩ Export month for IFS to write a CSV.

Still being confirmed

The exact column layout IFS expects for import hasn't been verified against a real IFS import yet — the mapping is fully configurable precisely so it can be tuned without any code changes once that's confirmed. If you get to that step during beta, flag anything that doesn't line up.

A few things worth knowing

Closing the main window doesn't quit the app — it keeps running in the tray/pill. Use Quit from the tray menu to actually exit.

The pill and tray icon always show the same colour as the project in the main list — that's the whole point of the colour-coding, so you can tell what's running from any of the three without reading text.

Your data folder is inside OneDrive, so it syncs on its own — no separate backup step needed.
